系统架构与部署说明

讲清楚四件事：整个系统的具体形态、DSH 和 WeKnora 的分工关系、WeKnora 部署方案、以及我们 wiki 知识库的最终形态。

1系统总览：三层形态

使用层 · 每人本地

DSH（DeepSeek Harness）—— 装在每个人的电脑上

装两个插件： paper-reader 读论文、对话带学、落盘 wiki（生产知识） dsh-weknora 4 个只读工具：检索/读文档/问答（消费知识）

▼ git 汇聚 / 批量导入
知识层 · 团队共享

wiki 知识库 —— 三层数据

本地真源 paper-wiki/（md 概念页 + 论文页 + graph.json 图谱） git 汇聚 team-wiki/（中心仓库，canonical 合并） 智能检索 WeKnora（向量 + 语义问答）

▼ 提供检索/问答 API
智能层 · 服务器

WeKnora + 模型

DeepSeek 大模型（LLM，问答/推理） 千问 qwen3.7-text-embedding-flash 向量模型（embedding，语义检索）

完整闭环：读论文（DSH 生产）→ 落盘 wiki → git 汇聚 → 导入 WeKnora → 全员检索（DSH 消费）→ 下次带学复用。

2DSH 和 WeKnora 的关系

一句话：DSH 是"手"，WeKnora 是"脑"；一个生产知识，一个检索知识。

DSH（本地）WeKnora（服务器）
定位使用端，装在每人电脑服务端，团队共享的语义检索 + 问答
职责读论文、带学、生成 wiki（生产）存文档向量、语义检索、RAG 问答（消费）
装什么paper-reader + dsh-weknora 插件Docker 容器（postgres/redis/app/docreader…）
数据本地 paper-wiki/（真源，git 管理）导入的文档向量（从 wiki 派生）

两者怎么连

DSH 里的 dsh-weknora 插件通过 HTTP 调 WeKnora 后端（baseUrl + apiKey），提供 4 个工具：weknora_search（检索原文段落）、weknora_read_document（读全文分块）、weknora_ask（RAG 问答）、weknora_list_knowledge_bases。

注意：dsh-weknora 只读不写——文档导入要靠 WeKnora 的 Web UI / CLI / API，不是由 DSH 写进去。

3WeKnora 部署方案

原则：PQC 数据敏感，优先内网自建，避免公网暴露

方案适合数据安全成本推荐
内网服务器（实验室/学校机器）团队同处一个内网最高，数据不出内网几乎为 0首选
私有云服务器（阿里云/腾讯云 VPS）团队分散、需远程需白名单 + HTTPS约 100~300 元/月次选
WeKnora Cloud 托管个人快速体验数据在第三方按量不推荐（PQC 敏感）
⚠️ 无论哪种方案，都不要把 WeKnora 直接暴露公网；云服务器务必配置安全组白名单（只允许团队 IP）、HTTPS、强密码、定期更新。

Docker Compose 部署步骤（以 Linux 服务器为例）

# 1. 准备环境
sudo apt update && sudo apt install -y docker.io docker-compose-plugin git

# 2. 拉取 WeKnora
git clone https://github.com/Tencent/WeKnora.git
cd WeKnora
cp .env.example .env

# 3. 编辑 .env（关键：模型配置，见第 4 节）
# 4. 启动（默认 6 容器：postgres/redis/app/docreader/frontend/nginx）
docker compose pull
docker compose up -d

# 5. 访问
#    Web UI:   http://服务器IP:80
#    后端 API: http://服务器IP:8080

硬件需求

最低 2 核 4G，推荐 4 核 8G；embedding 和 LLM 都调 API（不占本地算力），所以服务器不用 GPU，主要是跑检索和 PDF 解析。

4模型配置（.env）

两个模型，都是 OpenAI 兼容 API

# ===== LLM（DeepSeek 大模型：问答/推理）=====
LLM_MODEL_NAME=deepseek-chat
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的DeepSeekKey
LLM_PROVIDER=openai

# ===== Embedding（千问向量模型：语义检索）=====
EMBEDDING_MODEL_NAME=qwen3.7-text-embedding-flash
EMBEDDING_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
EMBEDDING_API_KEY=sk-ws-...（你的千问 key）
EMBEDDING_PROVIDER=openai

千问向量模型信息：qwen3.7-text-embedding-flash，201 种语言、上下文 131K、约 ¥0.125/M tokens（远低于大模型）。
⚠️ API key 不要写进 git 仓库，用环境变量注入；密钥已泄露的话去平台重置。

5wiki 知识库的最终形态

三层数据，各自职责不同、单向派生

① 本地真源（每人的 paper-wiki/）

concepts/*.md（概念页，全库唯一）+ papers/*.md（论文讲义）+ glossary.md（术语表）+ graph.json（知识图谱：实体 + prerequisite_of 前置→核心映射）

这是唯一可信数据源，git 管理，可 diff/回滚/迁移。

▼ git push（团队汇聚）
② 团队汇聚（team-wiki/ 中心 git 仓库）

users/<name>/wiki/（各人原文，全员共享）+ merged/（canonical 精选，review 后合并）+ graph.json（全局图谱，跨用户去重）

由 scripts/merge-wiki.mjs 把多人 wiki 合并去重；权限用 git 保护分支 + CODEOWNERS。

▼ 批量导入（WeKnora）
③ 智能检索（WeKnora）

向量检索 + 混合检索 + RAG 问答 + 知识图谱；dsh-weknora 插件让 DSH 里的 agent 直接检索/问答。

从 ①② 单向派生，只读消费，不改真源。

为什么这样分三层

本地真源保证「离线能用、可版本、可迁移」；git 汇聚解决「多人的知识去重、review、权限」；WeKnora 提供「语义搜索、问答」这种本地文件给不了的能力。三层单向派生——任何时候 WeKnora 挂了、git 乱了，真源（①）都还在。
